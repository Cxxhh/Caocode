Add one-click "Import to Caocode" to my API site. Caocode is a desktop AI coding app; how the import works: https://caocode.dev/upstreams

1. First find out what this site is:
   - new-api / one-api (it has System Settings → Chat Settings): no code needed. Tell me to add this entry in Chat Settings:
     { "Caocode": "https://caocode.dev/import#v=1&name=<site name>&protocol=anthropic&url={address}&key={key}" }
     and to try it once, signed in as an ordinary user, with that user's key, and to check the key imported is exactly the whole key the site shows.
   - Anything else (sub2api, or our own code): add an "Import to Caocode" button next to each key in the key / token list a signed-in user sees, as in step 2. What is imported is the site's user's own key, never the owner's or an admin's.

2. The button opens, in a new tab (target="_blank" rel="noopener noreferrer"):
   https://caocode.dev/import#v=1&name=<site name>&protocol=<protocol>&url=<API base URL>&key=<the whole key>
   - name: the site's name, as the site's settings have it.
   - protocol: anthropic (the site serves /v1/messages), openai-chat (/v1/chat/completions) or openai-responses (/v1/responses). Use anthropic where the site supports it; where keys differ (by group, say), pick by this key's.
   - url: the base URL users call the API at, as the site shows it to them, http or https; without /v1 for anthropic.
   - key: the user's whole key, not the masked one shown; if the list only has the masked one, fetch the whole key, as that user, when the button is clicked.
   - Encode each value with encodeURIComponent.
   - The parameters go after the #, never after a ?: browsers never send what follows a # to any server, so the key goes through neither caocode.dev nor any other server.

3. Label the button "Import to Caocode" and style it as the page's other buttons. Put Caocode's mark before the label: an <img> of the image online at caocode.dev, never a copy downloaded into the project, nor an SVG drawn or inlined.
   - Address: https://caocode.dev/brand/caocode-mark-<color>-<height>.webp
   - Color: black on light buttons, white on dark or colored (primary) buttons; where the site has light and dark themes, switch with them.
   - Size: the mark is 4:3. Pick its size by the label's, src the 1x image, and srcset the 2x and 3x for sharp screens:
     · Label 13–14px (small buttons, buttons in a table row): shown 16×12, heights 12 / 24 / 36
     · Label 15–16px (ordinary buttons): shown 24×18, heights 18 / 36 / 54
     · Label 18px or more (large buttons): shown 32×24, heights 24 / 48 / 72
     For example: <img src="https://caocode.dev/brand/caocode-mark-black-12.webp" srcset="https://caocode.dev/brand/caocode-mark-black-24.webp 2x, https://caocode.dev/brand/caocode-mark-black-36.webp 3x" width="16" height="12" alt="">
   - About 6px between the mark and the label, centered vertically. Give width and height, so nothing moves as it loads; leave alt empty, the label says it.
   - Where a square app icon fits (on an import guide, a card): https://caocode.dev/brand/caocode-icon-<size>.png, sizes 16, 24, 32, 48, 64, 96, 128, 256, 512. src the size shown, srcset the one twice that, for example: <img src="https://caocode.dev/brand/caocode-icon-32.png" srcset="https://caocode.dev/brand/caocode-icon-64.png 2x" width="32" height="32" alt="">
   - Where the site sets a CSP, add https://caocode.dev to its img-src.
   Besides these images, don't load any script or style from caocode.dev, and don't call caocode.dev from the backend.

4. When done, tell me which files changed and how to check it: the button should open caocode.dev/import, showing the site's name, the protocol, the URL and the key masked; with Caocode installed, it then asks to import.

     ### API hosts / API 域名: the hosts the base URLs are at, comma-separated, e.g. api.example.com, example.com.
     ### One line about it / 一句话介绍: a line in English and one in Chinese if you can, about 30 characters each, as "en: …" and "zh: …".

How the listing works

  • Your card is at the top of Caocode’s Settings → Models, among the sites that added the import, in a random order each time the page opens: nobody is always last.
  • A user with an upstream from your site (imported from your key page, say) always sees your card first, the others after it.
  • A click on it opens your site, with your promotion parameters if you like.
  • Nobody pays to be listed, and a site stays listed as long as its import works. A listing is not an endorsement.
  • A site is taken off when its import stops working, its domain changes hands, or it misleads users (passing itself off as an official API, say).

By hand: new-api, one line of settings

In System Settings → Chat Settings, add this entry. new-api fills in {address} and {key}, and every key in the token list gets a Caocode option:

{ "Caocode": "https://caocode.dev/import#v=1&name=YourSite&protocol=anthropic&url={address}&key={key}" }

Use protocol=openai-chat or openai-responses instead if that is what your users should speak to. Try it once, signed in as an ordinary user, with that user's key, and check the key imported is exactly the whole key the site shows.

By hand: any other site, a link

Next to each key, a link that opens, in a new tab:

https://caocode.dev/import#v=1&name=…&protocol=…&url=…&key=…
ParameterWhat it is
urlrequiredYour base URL, http or https. Without /v1 for Anthropic.
protocoloptionalanthropic (the default), openai-chat or openai-responses.
nameoptionalYour site’s name, as Caocode lists the upstream.
keyoptionalThe user’s key, whole.
voptional1.

Encode each value with encodeURIComponent. Put them after the #, never after a ?: browsers never send what follows a # to a server, so the key goes from your page to the user’s Caocode and nowhere else. caocode.dev’s page reads it, takes it off the address bar and opens Caocode, which shows the user what it is about to add and asks first.

Please don’t load any script from caocode.dev on your key page; a plain link is all it takes. The icons below are fine to load.
