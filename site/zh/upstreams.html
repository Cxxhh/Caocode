交给 AI 来做，瞬间完成曝光

在您站点的代码仓库里，把下面这段发给 AI 编程助手（Claude Code、Codex、Cursor……）。它会判断站点用的是什么并完成接入，new-api 系的站点连代码都不用改。

请帮我在我的 API 站点上接入「导入到 Caocode」一键导入。Caocode 是一个桌面 AI 编程客户端，接入说明见 https://caocode.dev/zh/upstreams 。

1. 先看清这个站点是什么：
   - new-api / one-api 系（有「系统设置 → 聊天设置」）：不用改代码。告诉我在聊天设置里加这一项：
     { "Caocode": "https://caocode.dev/import#v=1&name=<站点名>&protocol=anthropic&url={address}&key={key}" }
     并提醒我登录一个普通用户账号，用这个用户的令牌实际点一次导入，确认导入的 key 和站点上的完整 key 一模一样。
   - 其他（sub2api 或自研）：在用户登录后看到的令牌 / API Key 列表里，每个令牌旁边加一个「导入到 Caocode」按钮，按第 2 条实现。导入的是站点用户自己的令牌，不是站长或管理员的。

2. 按钮在新标签页打开（target="_blank" rel="noopener noreferrer"）：
   https://caocode.dev/import#v=1&name=<站点名>&protocol=<协议>&url=<API Base URL>&key=<完整 key>
   - name：站点名，用站点配置里的名称。
   - protocol：anthropic（站点提供 /v1/messages）、openai-chat（/v1/chat/completions）或 openai-responses（/v1/responses）。支持 anthropic 就用 anthropic；不同令牌走不同协议的（比如按分组区分），按这个令牌的实际情况选。
   - url：用户调用 API 的 Base URL，和站点上展示给用户的一致，http 或 https；anthropic 协议不带 /v1。
   - key：用户这个令牌的完整 key，不是打码后的显示值；列表里只有打码值的话，在点击时用该用户的登录状态再取完整值。
   - 每个值都用 encodeURIComponent 编码。
   - 参数必须放在 # 后面，绝不能放在 ? 后面：浏览器不会把 # 后面的内容发给任何服务器，key 不经过 caocode.dev 或任何服务器。

3. 按钮文字用「导入到 Caocode」，样式和页面上现有的按钮保持一致。文字前放 Caocode 标志：用 <img> 引用 caocode.dev 上的在线图片，不要把图片下载进项目，也不要自己画或内联 SVG。
   - 地址：https://caocode.dev/brand/caocode-mark-<颜色>-<高度>.webp
   - 颜色：black 用在浅色按钮上，white 用在深色或彩色（主色）按钮上；站点有深浅两种主题的，跟着主题切换。
   - 尺寸：标志宽高比 4:3。按按钮文字大小选显示尺寸，src 用 1x 那张，srcset 给高分屏加 2x、3x：
     · 文字 13–14px（小按钮、表格行里的按钮）：显示 16×12，高度 12 / 24 / 36
     · 文字 15–16px（普通按钮）：显示 24×18，高度 18 / 36 / 54
     · 文字 18px 以上（大按钮）：显示 32×24，高度 24 / 48 / 72
     例：<img src="https://caocode.dev/brand/caocode-mark-black-12.webp" srcset="https://caocode.dev/brand/caocode-mark-black-24.webp 2x, https://caocode.dev/brand/caocode-mark-black-36.webp 3x" width="16" height="12" alt="">
   - 标志和文字间隔 6px 左右，垂直居中。写上 width 和 height，加载前不会跳动；alt 留空，按钮文字已经说明了。
   - 地方够、想放方形应用图标时（比如导入说明、卡片里）：https://caocode.dev/brand/caocode-icon-<尺寸>.png，尺寸有 16、24、32、48、64、96、128、256、512。src 用显示尺寸那张，srcset 加 2 倍那张，例：<img src="https://caocode.dev/brand/caocode-icon-32.png" srcset="https://caocode.dev/brand/caocode-icon-64.png 2x" width="32" height="32" alt="">
   - 站点设了 CSP 的，把 https://caocode.dev 加进 img-src。
   除了这些图片，不要引用 caocode.dev 的脚本或样式，后端也不要请求 caocode.dev。

4. 做完后告诉我改了哪些文件，以及怎么验证：点按钮应打开 caocode.dev/import，页面上显示站点名、协议、地址和打码后的 key；装了 Caocode 的话，会弹出导入确认。

5. 验证通过后，帮我通知 Caocode 收录我的站点，在 Caocode 的 设置 → 模型 里展示（免费）。
   在 Caocode 的 GitHub 仓库开一个 issue 通知收录：https://github.com/Cxxhh/Caocode/issues/new?template=upstream-listing.yml
   - 装了 gh 并已登录的，用 gh issue create --repo caocode-dev/caocode --title "[Upstream] <站点名>" --body-file <文件> 直接提交；没有的话，把整理好的内容给我，我打开上面的链接自己贴。
   - 正文按下面的小标题顺序写（和 issue 表单一致），每项一段：
     ### Site name / 站点名称：卡片上显示的名称，不超过 24 个字符。
     ### Card link / 卡片链接：点击卡片打开的地址，可以带推广参数（aff、ref 等）。
     ### API hosts / API 域名：Base URL 所在的域名，逗号分隔，例如 api.example.com, example.com。
     ### One line about it / 一句话介绍：中文和英文各一行，每行不超过约 30 字，格式 "zh: …" 和 "en: …"。
     ### What your site runs / 站点系统：new-api、sub2api、one-api 或 Other / 其他。
     ### Where the import is / 一键导入的位置：用户在哪个页面、哪个按钮或菜单里找到「导入到 Caocode」。
     ### Logo：站点 Logo，正方形，PNG 至少 256×256（透明背景最好）或 SVG。
     ### Contact / 联系方式：Caocode 联系我确认素材的方式（邮箱、Telegram、微信等）。
     ### Rules / 规则：
     - [x] 登录用户都能在我的站点使用一键导入。
     - [x] 我了解收录不代表担保，卡片顺序随机；导入失效或误导用户的站点会被下架。
   - 命令行传不了图片：提交后提醒我把 Logo 和按钮位置的截图拖进 issue 的评论里。
   - 站点名、推广参数、联系方式这些拿不准的，先问我，不要编。

也可以挑一个按钮样式：点一下想要的按钮，复制的提示词就会带上它的样子。

展示规则

  • 卡片在 Caocode 的 设置 → 模型 顶部，和其他接入了一键导入的站点一起展示，每次打开顺序随机，谁也不会一直排在后面。
  • 用着您站点上游的用户（比如从您的令牌页一键导入过），卡片区里您的站点始终排在首位，其他站点排在后面。
  • 点击卡片打开您的站点，卡片链接可以带您的推广参数。
  • 展示完全免费，只要导入一直可用就一直展示；展示不代表 Caocode 为您担保。
  • 导入失效、域名易主或误导用户（比如冒充官方）的站点会被下架。

自己动手：new-api 加一行配置

在 系统设置 → 聊天设置 中加入下面这一项。new-api 会替换 {address} 和 {key}，令牌列表里的每个令牌都会多出 Caocode 选项：

{ "Caocode": "https://caocode.dev/import#v=1&name=您的站点&protocol=anthropic&url={address}&key={key}" }

如果用户应该走 OpenAI 接口，把协议换成 protocol=openai-chat 或 openai-responses。请登录一个普通用户账号，用它的令牌实际点一次导入，确认导入的 key 和站点上的完整 key 一模一样。

自己动手：其他站点放一个链接

在每个令牌旁放一个链接，在新标签页打开：

https://caocode.dev/import#v=1&name=…&protocol=…&url=…&key=…
参数含义
url必填Base URL，http 或 https；Anthropic 协议不带 /v1。
protocol可选anthropic（默认）、openai-chat 或 openai-responses。
name可选站点名称，即 Caocode 中上游的名称。
key可选用户的完整 key。
v可选1。

每个参数值都要用 encodeURIComponent 编码。参数必须放在 # 后面，不能放在 ? 后面：浏览器不会把 # 后的内容发给任何服务器，key 只会从您的页面直接到用户的 Caocode。caocode.dev 的页面读取后会把它从地址栏中清除并打开 Caocode，Caocode 会先向用户展示要添加的内容，经确认后才添加。
