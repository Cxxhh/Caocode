# 切换 Windows 与 WSL2 Codex

在左侧栏顶部选择 **Windows · Codex** 或 **WSL2 · 发行版名称**，然后点击 **打开项目**。
Windows 默认打开 Windows 用户目录；WSL2 默认打开所选发行版的 Linux 用户目录。
每个环境分别记住上次打开的项目目录，重启应用后继续保留。目录已被删除时重新从用户目录开始。

WSL2 项目通过 Windows 文件选择器浏览 `\\wsl.localhost\发行版\home\用户名`，
保存为 UNC 路径；实际执行时转换为该发行版内的 Linux 路径，并运行其中的 `codex app-server`。
Windows 项目直接运行 Windows Codex。Windows 和每个 WSL2 发行版都需要各自安装、登录 Codex CLI。

切换环境后，项目列表和会话历史立即切换到该环境，其他环境的项目暂时隐藏；
切回时恢复原来打开的对话和项目。每个 WSL2 发行版分别显示自己的项目与历史。
切换时先显示已保存的会话目录，再刷新最近一批（最多 100 条）；30 秒内切回已经刷新的环境，
直接恢复已有内容。较早的会话点击环境选择器下方的 **加载更早会话** 逐批读取。
目录缓存保存在应用数据目录的 `cache/session-index.json`，重启应用也能先显示历史；
只缓存标题、时间和项目路径，对话正文仍在打开会话时读取。

环境选择器下方始终显示会话数、加载状态、刷新和重试入口。读取时可继续打开项目、
使用已有会话或切换环境；Windows 与各 WSL2 发行版互不等待。连续 15 秒未收到结果会结束加载，
保留现有内容并提示重试。首次无缓存时仍需等待该环境的 CLI 启动和首批查询。
打开项目（包括已经打开过的项目）会单独刷新该项目的历史，逐批显示，无需先新建对话。
正在执行的任务继续在原环境运行，各自的登录、会话和配置保留。
文件选择、添加工作区文件夹、聊天输入框旁的项目选择入口使用相同的环境选择。
选择另一环境的目录时会提示重新选择，取消选择不会创建项目。

**设置 → 模型 → Codex CLI** 也可以切换环境，分别配置可执行文件和 `config.toml`。
Windows 使用 `codexCli.path.windows`、`codexCli.configPath.windows`；WSL 使用
`codexCli.path.wsl.发行版`、`codexCli.configPath.wsl.发行版`。留空使用该环境默认配置。
原有未分环境的路径设置继续用于兼容的环境。**设置 → 更新** 的 CLI 检查和更新跟随所选环境。

此切换入口在 Windows 桌面版提供，只列出 WSL2 发行版。Linux、macOS 的原有项目打开方式保持一致。

## FastIDE 的 WSL 文件访问

选择 WSL2 项目后，FastIDE 自动通过 `wsl.exe` 的标准输入输出连接该发行版内的原生文件服务。
无需启动 SSH 服务、配置密钥或开放端口。应用携带 Linux x64/arm64 服务，首次使用时安装到
`~/.caocode-server/<服务版本>/`；同一发行版的文件树、编辑器、搜索和图片预览共享连接。
应用退出时关闭服务，连接失败后刷新文件树可重连；连接中断后重新打开文件再保存，写操作不会自动重放。

文件树只读取当前目录，展开文件夹时再读取下一级；首次连接时显示“正在加载文件”。
项目索引、全文搜索、文件监听和保存都在 WSL 内执行，避免从 Windows 逐个遍历 Linux 文件，
并避开 WSL 挂载不支持 Windows 文件锁而导致的保存失败。保存继续检查外部修改冲突。
界面保留标准 UNC 路径，支持在 Windows 文件管理器中显示、拖拽和复制文件；已有的正斜杠
UNC 历史记录和扩展 UNC 路径会在访问前转换，不必重新添加项目。

本机 WSL 使用此直连方式；SSH 入口继续用于其他机器。项目保存在 WSL 的 Linux 文件系统内，
Codex、搜索和文件服务都在同一环境工作。构建和开发启动脚本自动增量准备原生服务并打包，
安装后的应用无需 Dart SDK 或在线下载。

在 Windows 构建目录可运行诊断（只读项目，在临时子目录验证写入并清理）：

```text
dart run tool/caocode/check_wsl_files.dart Ubuntu-24.04-dev /home/noxae/Documents/Caocode
```

诊断输出连接、目录读取、索引、搜索和保存的耗时，并验证重命名、复制、二进制读取及监听。

选型依据：仅通过 UNC 读写会遇到 Windows 文件锁不受支持的问题，大量目录遍历也产生跨系统开销；
SSH 可以把计算放到 Linux，但本机 WSL 还要维护 sshd、认证和连接配置。
`wsl.exe` 复用相同的原生文件协议，直接启动 Linux 服务，因此作为本机 WSL 的默认通道。
项目保存在使用该项目的 Linux 环境内，也符合 [Microsoft 的文件系统性能建议](https://learn.microsoft.com/en-us/windows/wsl/filesystems)。
